# 山河纪部署文档

本文说明课程验收时如何把「山河纪 · 全国热门景点文旅门户」跑起来。项目采用前后端分离：Vue 3 前台、Spring Boot 3 接口、MySQL 8 数据库。

## 1. 环境要求

| 软件 | 版本 | 用途 |
| --- | --- | --- |
| JDK | 17 或以上（本仓库按 Java 17 字节码编译） | 运行后端 |
| Maven | 3.8 及以上 | 构建后端 |
| Node.js | 20 及以上，附带 npm | 构建或开发前台 |
| MySQL | 8.0 | 业务库 `shanhe` |
| Docker / Compose | 可选 | 一条命令拉起 MySQL、后端和前台 |

操作系统不限。开发与验收使用 UTF-8。数据库、JDBC 和应用时区统一为 `Asia/Shanghai`（`+08:00`），这样种子数据里的 `CURDATE()` 和统计图的“今天”是同一天。

仓库里的景点照片是已经压缩的 WebP，介绍视频只保存外链，不包含视频文件。提交前请删除 `node_modules/`、`frontend/dist/`、`backend/target/`，压缩包应控制在 10 MB 左右。

## 3. 准备 MySQL

用 root 导入 `sql/schema.sql` 即可。脚本会创建库 `shanhe`，并在末尾创建用户 `shanhe` / `shanhe123`，主机包括 `localhost`、`127.0.0.1` 和 `%`，然后 `GRANT ALL` 到 `shanhe.*`。这与 `application.yml` 里的账号一致，导入后可以直接启动后端，不必再手工建用户。

若密码需要改成别的值，同时修改 `schema.sql` 末尾和 `application.yml`。Docker Compose 的后端通过环境变量使用 root，不依赖这个账号。

导入时把会话时区设为东八区，否则临近午夜时统计窗口会偏一天：

```bash
mysql --default-character-set=utf8mb4 --init-command="SET time_zone='+08:00'" -u root -p < sql/schema.sql
mysql --default-character-set=utf8mb4 --init-command="SET time_zone='+08:00'" -u root -p < sql/data.sql
```

`schema.sql` 会 `CREATE DATABASE` 并 `USE shanhe`。再次导入会按外键顺序删除全部业务表再重建，订单、游记和账号都会清空。这只适合第一次初始化，或你故意重置演示库。已经有人在用的库不要靠整份 `schema.sql` 改表，应另写迁移语句。本轮已有库的增量语句在 `sql/migrate_v4.sql`，由 `scripts/apply_migrate_v4.py` 按信息架构判断后执行，可重复运行。

生成种子数据和示意图还需要 Python 包：`pip install bcrypt pillow`。`bcrypt` 用来给 `scripts/build_seed.py` 写密码哈希，`pillow` 用来给 `scripts/draw_diagrams.py` 画报告里的图。介绍视频的字段名是 `scenic_spot.video_url`，前台无视频时只提示浏览图集，不把字段名显示给游客。

导入后应能看到 14 张业务表，以及 24 个景点、72 张景点图、48 个票种、60 笔以上订单、10 篇游记、5 张首页横幅。

```sql
USE shanhe;
SHOW TABLES;
SELECT COUNT(*) FROM scenic_spot;
SELECT username, role FROM `user` WHERE username IN ('admin','linwan');
```

## 4. 启动后端

```bash
cd backend
mvn spring-boot:run
```

或先打包再运行：

```bash
mvn -DskipTests package
java -jar target/shanhe-portal.jar
```

默认端口 `8088`。数据源在 `src/main/resources/application.yml`：

- 地址：`jdbc:mysql://127.0.0.1:3306/shanhe`
- 用户：`shanhe`
- 密码：`shanhe123`

可用环境变量覆盖，Docker Compose 就是这样做的：`SPRING_DATASOURCE_URL`、`SPRING_DATASOURCE_USERNAME`、`SPRING_DATASOURCE_PASSWORD`。

启动成功后访问：

```bash
curl http://127.0.0.1:8088/api/health
```

返回 `{"code":0,"message":"ok","data":"山河纪"}` 即表示接口和统一响应格式正常。

## 5. 启动前台

```bash
cd frontend
npm install
npm run dev
```

开发服务器监听 `0.0.0.0:43123`，并把 `/api` 代理到 `http://127.0.0.1:8088`。浏览器打开：

<http://127.0.0.1:43123>

生产构建：

```bash
npm run build
```

产物在 `frontend/dist`。若单独用 Nginx 托管，需要把 `/api` 反代到后端，并把前端路由回退到 `index.html`。仓库里的 `frontend/nginx.conf` 已经写好这两条规则。

## 6. Docker Compose

在仓库根目录：

```bash
docker compose up --build
```

也可以双击项目根目录的一键脚本：macOS 为 `deploy-macos.command`，Windows 为 `deploy-windows.bat`。卸载用 `remove-macos.command` 或 `remove-windows.bat`。默认只删除容器、网络和本项目构建的镜像，数据库卷保留；加上 `--purge-data` 才删除数据。脚本不会卸载 Docker Desktop，也不会删除公共基础镜像或宿主机上的其他软件。

`docker-compose.yml` 里写了 `name: shanhe`，脚本也带 `-p shanhe`。把仓库解压成 `ShanHe-main` 这类目录名时，部署和卸载仍然操作同一组容器和数据卷。

端口写的是「宿主机:容器」。宿主机一侧读环境变量，没设置时用下面的默认值：

- MySQL：`13306:3306`（`SHANHE_MYSQL_PORT`）。root 密码 `root123`，库名 `shanhe`。容器内端口仍是 3306，后端的 JDBC 地址是 `jdbc:mysql://mysql:3306/shanhe`，不随宿主机端口变化。这样不会占用本机已经在听的 3306。初始化脚本只会在数据卷第一次创建时执行。
- 后端：`8088:8088`（`SHANHE_BACKEND_PORT`），使用 root 连接容器内的 MySQL。
- 前台：`43123:80`（`SHANHE_FRONTEND_PORT`）。

一键脚本的健康检查访问的是 `SHANHE_FRONTEND_PORT`。改了这个变量之后，打开的也是新端口。`SHANHE_WAIT_SECONDS` 默认 180，同时用于 `docker compose up --wait` 和随后的接口检查。

从宿主机连接 Compose 里的 MySQL 时用 `127.0.0.1` 和 `SHANHE_MYSQL_PORT`（默认 13306）。root / root123 可以登录，`schema.sql` 创建的 `shanhe` / `shanhe123` 也可以。

`scripts/apply_migrate_v4.py` 和 `scripts/oversell_check.py` 默认连本机安装的 MySQL：`127.0.0.1:3306`，用户 `shanhe`（环境变量 `SHANHE_DB_PORT`）。这是第 3 节的本机库，不是 Compose 发布出来的端口。要对着 Compose 的库执行时：

```bash
SHANHE_DB_PORT=13306 python3 scripts/apply_migrate_v4.py
SHANHE_DB_PORT=13306 python3 scripts/oversell_check.py
```

若部署时改过 `SHANHE_MYSQL_PORT`，这里的 `13306` 换成同一个值。`scripts/e2e_api.py` 只请求后端 HTTP，默认 `http://127.0.0.1:8088/api`，不连接 MySQL。后端宿主机端口改掉之后，需要同步改这个地址。

重置数据：

```bash
docker compose down -v
docker compose up --build
```

或先 `bash remove-macos.command --purge-data`，再重新部署。Windows 用 `remove-windows.bat --purge-data`。

## 7. 默认账号

| 角色 | 用户名 | 密码 | 说明 |
| --- | --- | --- | --- |
| 管理员 | admin | admin123 | 可进入 `/admin` |
| 游客 | linwan | user123 | 已有订单、收藏和游记 |
| 其他种子用户 | 见库表 | user123 | 用于评论和统计 |

登录页上也写了这两个账号。注册页可以新建游客，角色固定为 `USER`。

建议验收顺序：

1. 首页轮播、热门景点、路线、资讯。
2. 景点列表里搜索“黄山”，切换省份和价格。
3. 打开故宫详情，查看图集、介绍视频、票种、图片署名和评论。
4. 用 `linwan` 登录，预约一张票，在“我的订单”里取消。
5. 发布一篇游记，状态为待审核。
6. 用 `admin` 登录后台，在游记审核中通过，在数据统计页查看四张图。

## 8. 图片和视频

景点照片在 `frontend/public/media/images/`，数据库存 `/media/images/*.webp`。封面用缩略图，画廊用大图。`scenic_spot.video_url`、`video_credit` 和 `spot_image.credit` 保存视频地址与署名。作者、协议和原始页面汇总在 `docs/ATTRIBUTION.md`，前台页脚也有同一份说明。更换图片时只改这些字段或替换同名文件，不必改 Vue 或 Java。

视频为空时，详情页仍然渲染 `<video>`，并用封面做 poster，避免页面结构依赖媒体包是否到齐。

## 9. 常见问题

- 后端报错拒绝连接：MySQL 没启动，或账号密码与 `application.yml` 不一致。
- 中文变问号：导入时漏了 `--default-character-set=utf8mb4`。
- 统计图最后一天是空的：导入会话时区不是 `+08:00`，和 JVM 的上海时区差了一天。按第 3 节重新导入。
- 前台接口 401：令牌过期或未登录就访问订单、收藏、后台。重新登录即可。令牌默认 72 小时。
- 删除景点失败：该景点已有订单或仍被路线引用。应改为下架，而不是物理删除。
- 端口被占用：本机开发时改 `application.yml` 的 `server.port` 和 `frontend/vite.config.js` 的 `server.port`，两边代理一起改。Docker 部署时改 `SHANHE_MYSQL_PORT`、`SHANHE_BACKEND_PORT`、`SHANHE_FRONTEND_PORT`。容器内部的 3306 和 8088 不用改。

## 10. 提交压缩包

课程要求把代码和报告放在“学号+班级”文件夹中再压缩，体积不超过 50 MB，建议 10 MB 以内。本仓库不含 `node_modules` 和构建产物。打包前执行：

```bash
# 在项目上一级
zip -r 学号班级-山河纪.zip 山河纪 \
  -x '*/node_modules/*' '*/dist/*' '*/target/*' '*/.git/*'
```

报告正文在 `docs/网站设计报告.md`。用 Word 或 Typora 导出时，建议 A4、宋体小四、1.5 倍行距，并保留截图，页数会超过 40 页。
